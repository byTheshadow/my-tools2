# 深夜寿司屋 · 游戏规则

> 这份文档是规则的"唯一来源"。改数值时先改这里的说明，再改对应的代码位置（括号里标了在哪个文件）。

## 1. 一句话

在像素寿司屋里，按顺序完成 **捏饭团 → 放鱼片 → 上菜**，给点单的客人做对寿司，连击越高分越高。特殊菜式会在中间多一步（炙烧、围海苔）。每夜 180 秒，靠经营赚钱、升级小店。**游戏没有终点**：没有通关，也没有结局，更新靠往后追加夜晚、客人和玩法（见第 16 节）。

## 2. 核心循环（每个寿司三步）

| 步骤 | 操作 | 要点 |
|---|---|---|
| 1 捏饭团 | 按住屏幕，松手 | 白圈从外向内收缩，缩到金色圈时松手 |
| 2 放鱼片 | 点一下 | 传送带上离中线最近的鱼片落到饭团上，要对准中线 |
| 3 上菜 | 点客人 / 点垃圾桶 | 点了这道寿司的客人才算对；不要的点右下角倒掉 |

电脑键盘：`空格` 捏饭团 / 放鱼片，数字键 `1`–`5` 给对应座位（从左到右）的客人上菜，`X` 倒掉。

特殊菜式在"放鱼片"之后多一步，见第 15 节。

## 3. 判定

### 3.1 捏饭团
白圈半径 `r` 离金圈中心 `13px` 的距离 `d = |r - 13|`：

| 条件 | 判定 | 结果 |
|---|---|---|
| `d ≤ 金圈半宽` | 完美 | 饭团饱满（捏度 0.7） |
| `d ≤ 金圈半宽 + 5` | 不错 | 饭团略歪（捏度取实际值，限制在 0.5–0.85） |
| 更远 | 失败 | 松手太早 → "太松，散了"；太晚 → "太硬了"；压到底 → "捏碎了"。失败后 0.35 秒内不能再捏 |

金圈半宽 = 难度曲线给的值 + 保温饭桶升级（见 12.4）。

### 3.2 放鱼片
鱼片落下时与中线的水平偏差 `|dx|`：

| 偏差 | 判定 |
|---|---|
| ≤ 2.5px | 完美（正中） |
| ≤ 7px | 还行 |
| ≤ 13px | 歪了（仍然算放上去） |
| > 13px | 没放上：鱼片掉落，饭团保留，**连击清零**，可以再放 |

磨刀石升级会把这些判定整体放宽 1 / 2 / 3.5px（`steps/fish.js` 的 `dropSpec()` = `CFG.drop` + 磨刀石）。

### 3.3 完美寿司
饭团 = 完美 **且** 鱼片 = 完美；如果这道菜带炙烧或围海苔，那一步也必须是完美。完美寿司有专属音效和粒子，分数 ×1.5，上菜时还有打赏。

## 4. 计分

```
基础分 = 饭团分 + 鱼片分 + 炙烧分 + 围海苔分 + 40 + floor(耐心剩余比例 × 30)
若是完美寿司：基础分 = round(基础分 × 1.5)
连击 +1
得分 = round(基础分 × (1 + min(连击, 20) × 0.1))
```

| 项目 | 完美 | 不错/还行 | 歪了 / 有点皱 |
|---|---|---|---|
| 饭团分 | 30 | 15 | — |
| 鱼片分 | 30 | 15 | 5 |
| 炙烧分 / 围海苔分（只有对应做法才有） | 30 | 15 | 5 |

- 普通寿司理论最高 **585** 分（完美 + 耐心满 + 连击 20 层以上，倍率 ×3.0）。
- 带一步特殊做法的菜（炙烧、军舰卷）全完美时，基础分 160，×1.5 = 240，再乘满连击的 ×3.0，单份理论最高 **720** 分。
- 炙烧"有点焦"、围海苔"有点皱"只拿 5 分，而且这份就不再是完美寿司。
- 代码在 `steps/serve.js`（`EXTRA_SCORE`）。

## 5. 连击

- 每成功上菜一份 **+1**；倍率 `1 + min(连击, 20) × 0.1`，上限 ×3.0
- 以下情况 **清零**：捏饭团失败、鱼片没放上、上错菜、倒掉寿司、客人等不及离开、炙烧烧焦、海苔撕破
- 连击越高，难度越高（见第 7 节）

## 6. 客人

- 同时 **3~5 位**，座位数 = 3 + 扩建升级（加座位 2 档，见 12.4）；教学夜固定 3 座，不受扩建影响
- 座位的 x 坐标来自 `config.js` 的 `seatsBy`（3 / 4 / 5 座各一组）。**所有"按座位找人"的代码一律读 `G.seats[i].x`**
- 点击上菜按 `nearestSeat(x)` 只看位置、不看客人状态；客人在不在等菜由 `serveTo` 判断
- 开局依次出现，延迟写在 `levels.js` 的 `difficulty.firstSeatDelays`（五个，够 5 座用）
- 每位客人随机点一种当前已解锁的寿司，头顶气泡显示订单和耐心条。带 `from: { story }` 的专属菜在解锁前不进点单池
- 耐心：开局值和下限由难度曲线给（见第 7 节），再乘当前节奏段的倍率，竹编茶座升级最后加若干秒；耐心 < 30% 时客人会冒汗。**耐心是客人进门那一刻定下的**，所以节奏段的倍率按"进门时刻"生效
- 耐心耗尽：客人生气离开 + 连击清零；离开后多久来新客人由一夜的节奏分段决定（见第 7 节），`difficulty.seatRespawn` 只是兜底
- 上错菜：客人抖动、变脸，该客人 **不会** 因此离开，订单保留
- 传送带有 **55%** 的概率刷出"当前客人点的鱼片"，其余随机
- 特殊客人：占一个座位，头顶 ✦，规则见 [STORY.md](STORY.md)

## 7. 难度曲线与节奏

八夜的难度数值集中在 `data/levels.js` 顶部的 `CURVE` 表，一行一夜，由 `diffOf(n)` 展开成 `difficulty` 对象。改手感先改这张表。

| 夜 | 捏饭团(秒) | 金圈半宽(px) | 传送带 起始 → 最高 | 耐心 开局 / 下限(秒) |
|---|---|---|---|---|
| 1 | 1.15 | 4.00 | 26 → 50 | 22 / 12 |
| 2 | 1.10 | 3.75 | 28 → 53 | 21 / 12 |
| 3 | 1.05 | 3.50 | 30 → 56 | 20 / 11 |
| 4 | 1.00 | 3.25 | 32 → 59 | 19 / 11 |
| 5 | 0.95 | 3.00 | 34 → 62 | 18 / 10 |
| 6 | 0.90 | 2.73 | 36 → 65 | 16.7 / 10 |
| 7 | 0.85 | 2.47 | 38 → 68 | 15.3 / 9 |
| 8 | 0.80 | 2.20 | 40 → 72 | 14 / 9 |

每夜公式相同，起点来自上表（代码在 `game.js`）：

| 参数 | 公式 |
|---|---|
| 捏一个饭团的时间 | `max(0.55, start − 连击×0.02 − 秒×0.0015)` |
| 金圈半宽 | `max(1.5, start − 连击×0.12)`，再加保温饭桶 |
| 传送带速度 | `min(max − 慢速传送带, start + 秒×0.12 + 连击×0.6 + 节奏段加速)`，最高速下限 12 |
| 客人耐心 | `max(patMin, start − 秒×0.04) × 节奏段倍率 + 竹编茶座` |

这些每秒系数按 180 秒一夜调过。要是把 `duration` 改回 90 秒，每秒系数要加倍，否则后半夜的曲线会摊平。

单关可以用 `difficulty.torch = { center, half, dur }` 覆盖炙烧的火候参数，用 `difficulty.wrap = { half, dur, tear }` 覆盖围海苔的参数。

### 一夜的节奏（`js/pace.js`）

关卡写 `phases: 'std'` 用默认四段，也可以写数组自定义；不写则完全沿用旧行为。八夜都用 `'std'`，教学夜不分段。段长按关卡 `duration` 等比缩放。

| 段 | 时长(秒) | 客人间隔(秒) | 耐心倍率 | 传送带加速 |
|---|---|---|---|---|
| 开门 | 30 | 1.6 – 3.2 | ×1.10 | 0 |
| 正常营业 | 90 | 0.9 – 2.2 | ×1.00 | 0 |
| 夜宵高峰 | 45 | 0.35 – 1.0 | ×0.88 | +4 |
| 打烊前 | 15 | 2.2 – 4.0 | ×1.00 | 0 |

- "客人间隔"是座位空出来之后、下一位客人进门的间隔。
- 只有切入"夜宵高峰"时会弹提示，其余段静默切换（段里写 `announce: true / false` 可改）。
- 最后 8 秒不再放新客人（`STOP_SPAWN_LAST`）。
- 对外接口：`begin / tick / respawn / patienceMul / beltAdd / canSpawn / current`。

## 10. 视觉与声音规范

- 逻辑分辨率 **180 × 320**，整数倍放大，`image-rendering: pixelated`
- 字体：DotGothic16（像素点阵体，联网时加载；离线用系统字体兜底）
- 主色板：墙面紫黑 `#3a2c3f`、柜台木色 `#a8653a` / `#e8b77a`、砧板 `#e5bf88`、饭米白 `#f7f2e6`、金色强调 `#f2b134`、警示红 `#ff6b5b`
- 声音全部由 WebAudio 合成，无外部文件；按住捏饭团时音调随压力升高
- 手机支持震动反馈（完美、失败、上错菜）
- 开屏文字用 DOM，画布只画像素图形；CSS 用 `calc(var(--s)*Npx)`

## 11. 教学夜

- 第一次点「开始营业」自动进教学夜；之后可在选关页第一行重练。不算在正式夜里，不记最高分，不扣房租。
- 澄姐说话时全店暂停：传送带不动、客人耐心不掉、倒计时不走。点一下翻一句。
- 六步：打招呼 → 捏 1 个饭团 → 放 1 次鱼片 → 给客人上 1 份 → 倒掉 1 份 → 自由练习。前五步按需放开传送带和客人，自由练习才开始倒计时（75 秒）。
- 上菜那一步会固定来一位客人，点的正好是砧板上做好的那份，保证能成功。
- 失败不扣分也不打断，澄姐只安慰一句（每步一次）。
- 结算不报分数和称号，只有澄姐一句话，按上菜份数挑（0 / 4 / 8 份三档）。
- 脚本在 `js/data/tutorial.js`，判定与放开规则在 `js/tutorial.js`。

## 12. 经营与结算

代码在 `js/economy.js`，数值在 `config.js` 的 `econ` / `run`，每夜的房租水电在 `data/levels.js`。

### 12.1 记账

```
营业额 = Σ（售价 × 售价倍率）+ Σ 打赏
今夜盈利 = 营业额 + 剧情奖励
         − 房租（议价可减免）− 水电 − 食材成本（上菜的 + 倒掉的 + 做坏的 + 烧焦的 + 撕破的）
累计资金 += 今夜盈利          （可以为负，亏本照样往下玩）
```

| 项目 | 规则 | 在哪调 |
|---|---|---|
| 售价倍率 | `1 + min(连击, 10) × 0.03`，最高 ×1.3（和计分倍率分开算，免得高连击把房租变成摆设） | `econ.moneyComboStep / moneyComboCap` |
| 打赏 | 完美寿司额外 +售价的 15%；招财猫升级再加比例，并让普通寿司也有概率打赏（按完美打赏的 50% 给） | `econ.tipRate`、`econ.luckyTipRate`、升级数据 |
| 房租 | 每夜一个数，见第 9 节；议价升级按比例减免，账本里多一行"议价已减" | `levels.js` → `rent` |
| 水电 | （减免后的）房租 × 水电比例，取整 | `levels.js` → `utilityRate`（不写用 `econ.utilityRate`） |
| 剧情奖励 | 剧情 `give.money` 记进当夜账本，打烊时入账 | 剧情文件 |

食材成本：

| 情况 | 记多少 |
|---|---|
| 上菜成功 | 整份成本 |
| 倒掉做好的寿司 | 整份成本 |
| 捏饭团失败 | 固定 6（`econ.riceFailCost`） |
| 鱼片没放上掉了 | 该鱼片成本的一半（`econ.fishMissRate`） |
| 炙烧烧焦 | 整份倒掉，付整份成本，清连击 |
| 海苔撕破 | 同烧焦：整份倒掉，付整份成本，清连击 |
| 上错菜 | 不记，订单和寿司都还在 |

以上成本都再乘当夜的 `costMult`。

**只有"当前这一夜"才记账。** 当前夜由存档里的 `night` 决定；回头重玩已通关的夜是**练习**（只记最高分，不动资金）。教学夜也不记账。

### 12.2 闭店线、重做、Game Over

- **闭店线** = −(当夜**原房租** × 2)（`run.closeLineRentMult`）。议价只减账上的房租，不会让闭店线变近。打烊后"资金 + 今夜盈利"**低于**闭店线就是闭店；恰好等于不算。
- **重做次数**：最多存 2 次（`run.retryMax`），存档里记的是"已用次数" `retries`。
  - 闭店且还有次数：澄姐圆场，资金退回这一夜开始前的数值（存档 `nightStartMoney`），**夜数不变**，同一夜重做；`retries` +1。剧情进度、升级、图鉴、最高分全部保留；当夜的剧情奖励随账一起退回。
  - **平安过一夜**（没闭店）：`retries` −1（最少到 0），也就是续回一次重做的机会。
  - 闭店但次数用完：**Game Over**，`save.restartRun()`，回到第一夜，只清资金、夜数、重做次数。升级、图鉴、剧情、最高分都留着。
- 没闭店的打烊：资金入账，`night` +1，**最多到已有关卡数**。走到最后一个关卡后 `night` 停在那里，继续按那一夜的数值真记账；追加新关卡后，玩家自然接着往下走，存档不用动。
- 结算页：资金落到闭店线 × 0.5 以下（`econ.tightRatio`）但还没闭店时，账本底部多一行小字"账本有点紧了……"，并列出闭店线。

### 12.4 店铺升级

在小店页用**累计资金**购买，永久生效；**只能在不营业时买**，只能用手上有的钱（不会买到负数）。买东西会同步压低 `nightStartMoney`（否则"打烊后买东西 → 下一夜闭店回档"等于白送）。价格和效果写在 `js/data/upgrades.js`，逻辑在 `js/shop.js`。

效果写的是绝对值（该档的总效果），不是增量。价格定档思路：一档约等于中段一夜的全部盈利，二档 ×2.3，三档 ×2.1。

| 手艺 | 保温饭桶 ricetub | 3 | 320 / 760 / 1600 | 金圈半宽 +0.6 / 1.2 / 2 px |
| 设备 | 慢速传送带 slowbelt | 3 | 380 / 880 / 1750 | 传送带最高速 −5 / −10 / −16（下限 12） |

## 15. 特殊做法

做法在 `data/methods.js`，每个做法是步骤 id 的有序列表。放完鱼片后可以换轨，新步骤表必须包含已完成的步骤。

| 做法 | 步骤 | 用于 |
|---|---|---|
| nigiri 握寿司 | rice → fish → serve | 普通寿司 |
| aburi 炙烧 | rice → fish → torch → serve | 鳗鱼·炙烧 |
| gunkan 军舰卷 | rice → fish → wrap → serve | 鲑鱼籽军舰卷 |

### 炙烧（`steps/torch.js`）
按住火候条涨，焦香区（默认中心 0.71、半宽 0.09、满格 1.5 秒，随连击收紧）松手 = 完美；区外一圈 = 不错；过头 = 有点焦（小分）；松太早只是重来；按到满 = 烧焦（整份倒掉、付成本、清连击）。关卡可用 `difficulty.torch = { center, half, dur }` 覆盖。

### 军舰卷（`steps/wrap.js`）
鱼籽先放上饭团，再围海苔。屏幕下方有一条轨道（位置和炙烧的火候条一样），里面有一扇金色小窗从左走到右；手指的进度要跟住它。

**操作**
- 手指 / 鼠标在屏幕任意位置按下，向右拖（拖满约半个屏幕宽，最多 90 逻辑像素）。按得太靠右、拖不满 40 像素时会提示"再往左一点按"。
- 键盘：按住 `→` / `D` / `空格` 前进，`←` / `A` 后退。
- 中途松手：海苔弹回重来，没有惩罚。往回拖：起点跟着手指走，不会"欠账"。

**判定**（从按下到围完，手指在金窗里的时间占比）

| 占比 | 品质 |
|---|---|
| ≥ 80% | 服帖（perfect） |
| ≥ 55% | 围好了（good） |
| 更低 | 有点皱（meh） |

- **撕破**：拖的途中手指一直冲在金窗前面太多（超前 > `tear`），持续 0.3 秒，海苔撕破：整份倒掉、付成本、清连击。
- 围满之后还要等金窗走过 85% 才收口，所以一把划到头占不到时间便宜，只是品质低（有点皱），不会撕破。

**数值**（默认值，随连击收紧，`difficulty.wrap` 可覆盖）

| 参数 | 公式 |
|---|---|
| 金窗半宽 `half` | `max(0.09, 0.16 − 连击×0.004)` |
| 金窗走完的秒数 `dur` | `max(0.9, 1.4 − 连击×0.015)` |
| 超前多少算撕破 `tear` | 0.38 |

围海苔的品质写进寿司（`wrapQ`），得分见第 4 节：服帖 +30 / 围好了 +15 / 有点皱 +5；想算完美寿司，饭团、鱼片、围海苔三项都要是完美。所以军舰卷的打赏比普通寿司难拿。

## 16. 无尽与更新

游戏没有结局，也没有通关画面。

- 玩到当前最后一个关卡后，`night` 停在那里，每夜继续按那一夜的数值真记账、真闭店。
- 新增关卡 = 在 `data/levels.js` 末尾追加一个对象。已经停在旧最后一夜的玩家，下一次打烊没闭店就会走进新的一夜。
- 约定：**第 8 夜之后房租和进货价不再往上涨**，难度停在第 8 夜的水平；新增夜晚靠新客人、新食材、新玩法来拉新鲜感，而不是继续抬房租。这样停在最后一夜的玩家不会陷入"越往后越必然崩盘"的循环。
- 重做机会每平安过一夜续回一次（见 12.2），所以长期游玩不会因为偶尔一次亏钱就被清档。
